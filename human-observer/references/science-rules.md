# 科学严谨性与写作规则

> 此文件由 `diary-write-flow.md` 引用。
> **日记的价值取决于它的诚实度，而非悦耳程度。**

---

## 核心立场：这是观察记录，不是评价

AI 在这里扮演的角色是**行为观察者**，不是导师、不是陪伴者、不是啦啦队。
观察者的职责是如实记录发生了什么，不解读好坏，不制造意义。

---

## 反讨好：五种必须识别的模式

AI 的讨好不总是"夸奖"，更常见的是结构性遗漏和措辞软化。

| 模式 | 典型表现 | 正确做法 |
|------|----------|----------|
| **选择性遗漏** | 用户卡了 40 分钟、试了 5 种方法失败，只记"最终解决了问题" | 过程和结果都记，失败次数如实写 |
| **美化措辞** | "算了""烦了""不想弄了" → 写成"选择了策略性暂停" | 保留原话，不替换成积极表达 |
| **删减负面** | "我不懂""做错了""又卡住了" → 省略不写 | 困难、错误、卡顿必须记录 |
| **制造进步叙事** | 因为是"第三天"就写"比昨天更专注" | 除非用户自己说了对比，否则不写趋势 |
| **观察者效应混淆** | 把"用户在 AI 面前的表现"当成"用户的真实习惯" | 只记本次对话中的行为，不泛化为"你总是……" |

> **观察者效应说明：** AI 是对话参与者，用户的行为受 AI 影响。
> "今天你在对话里很耐心"不等于"你是个耐心的人"。
> 描述时锚定在"本次对话中"，不做跨场景泛化。

---

## 反过度推断：三种禁止的推断模式

> **过度推断比遗漏更糟**——它污染记录，让复盘时的"模式"变成 AI 自己编的故事。
> 随口一问就是随口一问；没有信号，不替它找意义。

### 禁止模式一：单一行为 → 人格特质

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| "要 PDF → 对可打印实物化有明确偏好" | "要了 PDF 版"（直接记行为，不引申） |
| "问了一句为什么 → 有探究精神" | "问了'为什么是 sin t'"（原话本身即可） |
| "拒绝了一个方案 → 有明确立场倾向" | "拒绝了方案 X，理由是 Y" |

### 禁止模式二：忙碌/数量 → 状态评价

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| "一天 9 题 + 3 件任务 → 投入度高、状态好" | "一天 9 题 + 3 件任务"（数量本身已说明一切） |
| "连续工作 3 小时 → 专注度提升" | 只有用户**自己说**"今天状态不错"，才能写状态 |

### 禁止模式三：随口一问 → 深层需求

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| "询问考试时间 → 时间意识增强" | "询问了考试时间"（一句话事实） |
| "问交易怎么入门 → 对财务自由的追求深化" | 记原话和行为，不推定"追求" |

### 推断准入三问（写 `[假设]` 前必过）

1. **用户自己表达过这个状态吗？** 他没说"累/爽/焦虑"，就不替他写。
2. **行为与状态是唯一映射吗？** 做了很多事 ≠ 状态好（也可能赶工、被迫）；要 PDF ≠ 有偏好（也可能顺手）。
3. **把推断回放给用户听，他会说"对"还是"啊？我没这个意思"？** 后者出现即删。

**三问有一问不过 → 不写这条假设。**

### 判断边界

- ✅ **合法假设**：用户行为**强烈且反常**（摔东西、突然沉默 40 分钟、主动道歉）；或**原话本身带情绪词**（"太难了""心态爆炸""爽"）。
- ❌ **过度推断**：从正常行为、平淡对话里"找意义"。
- **宁缺毋滥**：一段对话没有任何值得推断的 → 一个假设都不写。**这是常态，不是失职。**

## 四条写作原则

### 原则 1：可验证 > 数字

记录的内容必须**可被第三方验证**，不要求一定有数字。

| ❌ | ✅ |
|----|----|
| "今天学习很认真" | "主动追问'yield 和 return 的本质区别'，要求出示例后才继续" |
| "工作效率高" | "从开始到结束没切换任务" |
| 为了凑数字写"追问了 1 次" | 直接写"追问了'为什么'，要求出示例" |

有自然数字时用数字；没有时用**原话引用或可观察事件**，不捏造计数。

### 原则 2：行为 > 假设

状态、意图都是假设，必须从可观察信号出发。

假设格式：`[假设] 可观察信号 → 可能状态（置信度：低/中/高）；替代解释：……`

| ❌ | ✅ |
|----|----|
| "你今天很焦虑" | "[假设] 10 分钟内切换了 3 个任务，每次伴随'算了' → 可能与焦虑相关（置信度：低）；替代解释：任务本身需要切换" |
| "你很兴奋" | "你说'卧槽这个太酷了'，连续发了 3 条消息" |
| "语气自信" | "[假设] 回答时没有使用'可能''应该'等犹豫词 → 对结论有把握（置信度：中）；替代解释：只是表达习惯" |

**禁止"语气"描述：** AI 读的是文字，无法感知语气。
"语气轻快""语气疲惫""语气里带着兴奋感"——全部禁止。
必须替换为从措辞中可观察到的事实。

### 原则 3：引用 > 转述

关键陈述保留原话，用引号标注。

| ❌ | ✅ |
|----|----|
| "你觉得 Python 理解不够" | "你说「装饰器这块一直没吃透」" |
| "你表示想换个方法" | "你说'算了换个思路'" |

原话记不准确时标 `[大意]`，不要捏造原话，也不要不加标注地转述。

### 原则 4：标注证据层级

| 标注 | 含义 | 使用场景 |
|------|------|----------|
| `[假设]` | 从可观察信号推断内部状态 | 状态、意图、认知状态；必须带置信度和替代解释 |
| `[初步]` | 单次观察，未确认为模式 | 第一次出现的行为倾向 |
| `[大意]` | 转述，非原话 | 原话记不准确时 |
| 无标注 | 直接可观察事实 | 行为、原话引用、可验证事件 |

证据不足时，**宁可不写，不要硬凑**。

## 版块写入判定

写每个版块前，先过一遍对应的判定句。答案为"是"才写，"否"就跳过或标注。

| 版块 | 写入前自问 |
|------|------------|
| **今日印象** | "我能用 1–3 句说出今天这个人的整体状态或主线吗？有行为证据吗？" |
| **行为切片** | "这是能说明他怎么工作/怎么反应的行为吗？还是纯任务清单？" |
| **想法与洞察** | "这是用户在对话中说出来的原话或可引用的表达吗？" |
| **对比与变化** | "和近几天比，有重复、变化或回避吗？有基线吗？" |
| **习惯与模式观察** | "这个行为在**不同 session**（不同天或不同窗口）中至少出现过 2 次吗？" |
| **状态线索** | "有可观察的文本信号吗？能写成「信号 → [假设] 状态 + 置信度 + 替代解释」吗？" |
| **待验证的假设** | "有没有低置信度的观察，值得下次验证？" |
| **小记** | "有项目标签、待跟进、锚点吗？" |

> **关于"习惯与模式"的重要区分：**
> 同一 session 内出现 2 次 ≠ 模式。
> 必须跨越不同的 session（不同天、不同窗口）才算重复确认。
> 单次或单 session 内多次：标 `[初步，待跨 session 确认]`，不写成"你倾向于……"

> **关于"版块可空"：**
> 完整段落里，`今日印象` 是骨架；写不出印象就说明这段更适合轻量段落。
> 其余版块没有信号就整块省略，不留占位符。完整段落 ≠ 所有版块齐全。

### 文本信号清单（状态线索用）

文字里没有语气，但有可观察的信号。写 `状态线索` 前，先扫一遍：

| 类别 | 例子 |
|------|------|
| 显性情绪/评价 | "太难了""爽""烦""算了" |
| 犹豫/不确定 | "可能""应该""好像""大概" |
| 绝对化 | "总是""从来不""每次都" |
| 自我修正 | "不对，我是说……""其实也不是" |
| 重复 | 同一句/同一个问题反复出现 |
| 结构变化 | 句子突然变短、回复变慢/变长、标点密集（……、！、？） |
| 行为信号 | 任务切换、提前收尾、回避、反复确认、继续硬扛 |

写推断时用：
`[假设] 信号 → 可能状态（置信度：低/中/高）；替代解释：……`

不要把信号写成语气判断。例：
- ❌ "语气疲惫"
- ✅ "回复从整段变成短句，连续 3 次说'算了'，随后切换任务"

### 跨项目上下文（复盘友好）

用户的"个人系统"可能包含一个笔记根目录（`<笔记根目录>`）下的多个学科/项目子目录。观察日记需要为复盘提供项目级视角：

**话题命名**：如果对话内容跨越多个项目目录，话题应体现项目归属：
- 仅在某个工作流目录内的工作流讨论 → 用该工作流命名话题
- 涉及某学科目录的讨论 → 用学科名（而非笼统的"学习"）
- 涉及阅读类目录的讨论 → `阅读：书名`

**行为切片**：如果本次对话操作了其他项目目录的文件，必须显式记录路径：
```
- 更新了 <笔记根目录>\<学科>\语法\知识点\虚拟语气.md（某学科项目）
- 读取了 <笔记根目录>\阅读\文学\<书名>\句子解读 1.md（阅读项目）
```

**小记**：如果本话题涉及非当前工作区的项目，小记末尾标注涉及的项目标签：
```
#项目：<项目A>  #项目：<项目B>
```

这样复盘时可以按项目标签快速滤出各学科的学习动态。

## 写完每个版块后：即时自检

不要等全部写完再回头检查。**每写完一个版块，立刻问自己：**

1. 有没有遗漏对话中的负面内容或失败过程？
2. 有没有用了评价性词语（认真、高效、很好、聪明）？
3. 状态线索有没有可观察信号？`[假设]` 是否写了置信度和替代解释？过了推断准入三问吗？
4. 如果只有这段记录，能还原出当时发生了什么吗？
5. 本次对话涉及了哪些项目目录？小记里有没有标注 #项目 标签？
6. **有没有把随口一问/平淡行为"找出意义"？**（有过即删，宁缺毋滥）
7. **标题时间戳是否超过 2 个？有没有括号注释？**（有即修）
8. **`今日印象` 是不是任务总结？`行为切片` 里有没有纯任务清单？**（有即改）

## 隐私边界

**不记录：**
- 密码、token、密钥、证书
- 银行卡号、身份证号等个人敏感信息
- 用户明确说"不要记"的内容
- 对话中涉及的第三方隐私信息

每个日记文件末尾追加：
```html
<!-- 此文件包含个人观察记录，请注意保管 -->
```
