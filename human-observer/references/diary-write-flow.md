# 日记写入流程

> 完整执行手册。进入此文件后不需要跳回 SKILL.md 查任何内容。
> 按决策树顺序执行，每个节点只有一个判断。

---

## 决策树总览

```
[准备] 时间+日期（系统命令，两步）→ agent-name（查注册表）→ 话题（查注册表归一化）
    ↓
[定位文件] <DIARY_DIR>/YYYY-MM/YYYY-MM-DD.md
    ※ DIARY_DIR 来自环境变量 HUMAN_OBSERVER_DIARY_DIR；YYYY-MM 取自系统命令日期；当月子目录不存在则创建
    ↓
[读文件] 文件存在？
    否 → 创建文件
    是 → 读取全部
    ↓
[判断] 今天已有此话题？（任意 agent）
    是 → 补写路径
    否 → 首次写入路径
         ↓
    近 3 天有此话题？
         否 → 情况 A（全新）
         是 → 提取基线 → 有新内容？
                              否 → 告知用户，停止
                              是 → 情况 C（跨天续写）
    ↓
[信号判定] ⭐ 本段写「完整」还是「轻量」？
    ↓
[写入] 按对应模板写
    ↓
[收尾] 有待跟进项？→ 同步追加到 _followups.md
```

---

## 准备阶段

### 1. 获取时间戳（必须用系统命令，禁止推断）

**获取完整日期+时间，两步独立执行：**

```bash
date +%H:%M                                      # macOS / Linux（优先尝试）
powershell -Command "Get-Date -Format 'HH:mm'"  # Windows（date 不可用时）
```

```bash
date +%Y-%m-%d                                    # macOS / Linux（优先尝试）
powershell -Command "Get-Date -Format 'yyyy-MM-dd'"  # Windows
```

**⚠️ 严禁行为：**
- 禁止仅获取时间就推断日期
- 禁止根据已有日记文件的修改时间推断"今天"
- 禁止根据 `<env>` 中的 `Today's date` 推断（那个日期可能是会话开始时冻结的，跨天不更新）
- **日期必须来自当前执行的系统命令，不接受任何其他来源。**

**确定写入路径**：`<DIARY_DIR>/YYYY-MM/YYYY-MM-DD.md`
- `DIARY_DIR` 来自环境变量 `HUMAN_OBSERVER_DIARY_DIR`（激活阶段已确认）
- `YYYY-MM` 取自系统命令返回的日期，如 `2026-10`
- 当月子目录不存在 → 自动创建
- 示例：`<DIARY_DIR>\2026-10\2026-10-13.md`

### 2. 确定 agent-name（查注册表）

读取 `_topics.md` → 「Agent 注册」表，选取当前 agent 的**注册名**。

- 表中有匹配 → 用注册名
- 无匹配 → 询问用户后，追加注册

**规则**：注册名一律英文小写 + 连字符（如 `agent-a`），不许中英混写。

### 3. 归一化话题（查注册表）

读取 `_topics.md` → 「活跃话题注册」表。

**提取候选：**
- 用户给出 `[话题]` → 以此为候选
- 用户未给出 → 根据对话内容推断候选，**向用户确认后**再继续

**查表流程：**

| 情况 | 处理 |
|------|------|
| 候选命中活跃表（含别名） | 用注册名 |
| 候选命中历史话题表 | 告知用户"此话题已休眠，确认重新激活？"→ 激活则移回活跃区 |
| 候选是新话题 | 按 `_topics.md` 的注册流程：注册 → 写入 → 小记注明"新话题已注册" |

**命名要求**：简洁（≤10 字）、稳定（不绑老师/版本/单次任务）、语义明确。

## 首次写入路径：锚点检查

读取近 3 天的日记文件（**不限 agent**）：

```
<DIARY_DIR>/<对应月份>/<昨天>.md
<DIARY_DIR>/<对应月份>/<前天>.md
<DIARY_DIR>/<对应月份>/<大前天>.md
```

**⚠️ 跨月处理**：近 3 天可能跨越月份（如今天是 11-01，大前天在 10 月）——每一天的目录按该天自己的月份定位，不要统一用今天的月份。

**没找到 / 最近记录超过 30 天** → 直接进入情况 A。

**找到了** → 建立基线清单：

```
基线已有（不写入）：
  - [历史段落中的具体条目]

本次独有（写入）：
  - [今天对话出现、基线未覆盖的内容]
```

| 基线对比结果 | 处理 |
|-------------|------|
| 「本次独有」为空 | 告知用户"今天关于 [话题] 均已记录"，**停止，不写入** |
| 「本次独有」有内容 | 进入情况 C |
| 无法区分今天和历史 | 告知用户基线内容，问"今天新发生的有哪些？" |

## ⭐ 信号判定（写完整段还是轻量段）

**这是控制记录质量的核心环节。** 写任何段落前，先判断本次对话的观察价值。

**过一遍这个判定：**

> 本次对话中有没有出现以下任意一项？
> ① 用户的**原话**带情绪信号（"太难了吧""心态爆炸""爽"）
> ② 用户的**行为**与已知模式形成重复（第 2 次以上出现）
> ③ 发生了**可记录的决策/转向/冲突**（新方案、放弃、边界争执）

| 判定结果 | 写什么 |
|----------|--------|
| 有任意一项 | **完整段落**（按模板，有信号才写，无信号的版块直接省略） |
| 都没有（例行公事、随口一问、平淡对话） | **轻量段落**（印象 + 行动要点 + 小记，2-8 行） |

**轻量段落不是"偷懒"**——它是对"没发生什么特别的事"的如实记录。
**但也不能滥用**：如果连续多天都是轻量段落，说明值得检查"是否漏掉了弱信号"。

## 写入前：重新读取文件

**无论走哪条路径，写入前必须重新读一次文件**，防止其他窗口并发写入导致内容被覆盖。

## 标题规范

```
## [agent-name | topic] HH:MM 观察
```

**时间戳规则（同一天多次追加时）：**

| 触发次数 | 标题写法 |
|----------|----------|
| 1 次 | `09:00` |
| 2 次 | `09:00 / 21:30` |
| 3 次及以上 | `09:00 / 21:30`（只保留**首次和最近**，中间不写） |

**禁止**：标题里加括号注释。
- ❌ `## [agent-a | topic-a] 21:38 观察（本轮只讨论方案——未改代码）`
- ✅ `## [agent-a | topic-a] 21:38 观察`（注释放段落内首行）

---

## 写作规则（写每一条前过一遍）

完整规则见 `references/science-rules.md`。核心提示：

- **不讨好**：失败、卡顿、放弃——必须记录，不得省略或美化
- **行为 > 假设**：状态必须有可观察信号，格式 `[假设] 信号 → 状态（置信度 + 替代解释）`
- **引用 > 转述**：关键陈述保留原话，不确定标 `[大意]`
- **禁止语气描述**：AI 读的是文字，不能写"语气自信""语气疲惫"；写措辞、结构、行为
- **禁止过度推断**：随口一问 ≠ 探索欲；顺手要 PDF ≠ 有偏好（详见 science-rules.md 推断准入三问）

## 情况 A：全新话题

### A-1 完整段落模板

```markdown
## [agent-name | topic] HH:MM 观察

### 今日印象
<!-- 1–3 句：先给整体感觉，再给行为证据；不要写成任务总结。 -->
-

### 行为切片
<!-- 3–5 条；每条是「行为 → 这说明什么」。纯任务清单留在项目笔记。 -->
-

### 想法与洞察
<!-- 写入判定：这是用户说出来的原话或可引用的表达吗？ -->
-

### 对比与变化
<!-- 与近几天比：什么重复了、什么变了、什么被回避了；没有基线就删除。 -->
-

### 习惯与模式观察
<!-- 写入判定：这个行为在不同 session 中出现过 ≥2 次吗？单次标 [初步，待跨 session 确认] -->
<!-- 无内容 → 整个版块删除，不留占位 -->
-

### 状态线索
<!-- 只写可观察的文本信号；推断用 [假设] 格式；无信号整块删除。 -->
- 可观察：...
- [假设] 信号 → 可能状态（置信度：低/中/高）；替代解释：...

### 待验证的假设
<!-- 低置信度观察、替代解释、下次怎么验证；没有就删除。 -->
-

### 小记
- 本次对话涉及的项目目录 → 用 `#项目：XXX` 标注
- 待跟进项（如有）→ 写在这里，同时同步到 _followups.md
-
```

### A-2 轻量段落模板

```markdown
## [agent-name | topic] HH:MM 观察

### 印象
- 一句整体感觉（可观察、可回放）。

### 行动要点
- （2–4 条，只记事实，不做推断）

### 小记
- 待跟进项（如有，同步到 _followups.md）
- #项目：XXX
```

---

## 情况 B-1：当前 agent 今天已有此话题段落

- 各版块追加新内容，只写今天新发生的
- 标题时间戳按「标题规范」更新：最多保留首次和最近两个
- 用户说"分开写" → 强制新建段落，不合并

## 情况 B-2：其他 agent 有，当前 agent 今天没有

- 新建当前 agent 的段落
- 小记注明：`参见今日 [other-agent | topic] 段`

---

## 情况 C：跨天续写

- 只写「本次独有」清单中的内容
- 小记标注锚点：

```markdown
### 小记
- 锚点：上一次记录于 MM-DD [agent-name | topic] 段（最后记录：XXX）
```

## 内容预算（防膨胀）

| 段落类型 | 目标行数 | 说明 |
|----------|:---:|------|
| 完整段落 | ≤ 60 行 | 行为切片 3–5 条；超过说明明细过多 |
| 轻量段落 | 2-8 行 | 印象 1 句 + 行动要点 2–4 条 |

**明细压缩规则**：技术明细（逐题记录、公式清单、commit 列表、文件清单）**不进观察日记**——它们属于学科笔记/项目笔记。观察日记只记：
- 明细的**摘要**（"9 题错 2 题"而不是每题都列）
- 提炼出的**模式**（"同一病根第三次出现：对错对象"）
- 关键**原话**

> 反例：某日日记逐题列了 9 道数学题含公式（40+ 行）——这些明细应在学科笔记里，日记只需"9 题错 2 题，病根：凑微分后对错对象（本月第三次）"。

## 写入后：收尾

1. **读回文件**，验证段落存在
2. **同步待跟进**：如果本次小记有"待跟进"项 → 追加到 `_followups.md` 的「进行中」区（带日期和来源段落）
3. **向用户简短确认**：

```
✓ 已写入 2026-10/2026-10-13.md → [agent-a | topic-b] 21:30  #项目：topic-b
  类型：完整段落（信号：原话"这有点太难了吧"）
  新增：行为切片 3 条，假设 1 条，待跟进 2 项（已同步 _followups.md）
```
