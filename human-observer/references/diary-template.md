# 观察日记格式模板

> 格式参考与示例。每个版块内嵌写入判定，AI 写之前先过判定句。
> **先做信号判定（完整 vs 轻量），再进入对应模板。**

---

## 版块写入判定速查

| 版块 | 写入前自问 | 写不了时 |
|------|------------|----------|
| **行动与体验** | 这是本次对话中发生的、可被第三方验证的行为吗？ | 跳过，不硬凑 |
| **想法与洞察** | 这是用户说出来的原话或可引用的表达吗？ | 跳过，不转述 |
| **习惯与模式观察** | 这个行为在**不同 session** 中出现过 ≥2 次吗？ | 单次标 `[初步]`；无内容整块删除 |
| **情绪与状态** | 有具体行为证据，能写成 `[推断] 行为 → 状态` 吗？过三问（见 science-rules） | **无内容整块删除，不留占位** |

> ⚠️ **完整段落 ≠ 四版块齐全**。只有真的观测到信号才写对应版块。
> 平淡对话写轻量段落（见示例 5、6）。

---

## 标题规范

| 触发次数 | 写法 |
|----------|------|
| 1 次 | `## [agent-a | 外语] 09:00 观察` |
| 2 次 | `## [agent-a | 外语] 09:00 / 14:30 观察` |
| 3 次及以上 | `## [agent-a | 外语] 09:00 / 21:30 观察`（首次 + 最近） |

**禁止**：标题加括号注释；agent 名中英混写；topic 不用注册名。

---

## 段落合并规则

| 条件 | 处理 |
|------|------|
| 同 agent + 同话题，同一天 | 追加到已有段落，标题时间戳按规范更新 |
| 同 agent + 不同话题 | 独立段落（新话题先查 `_topics.md`） |
| 不同 agent + 任意话题 | 独立段落 |
| 用户说"分开写" | 强制新段落 |

---

## 示例 1：完整段落 — 跨天续写 + 模式升级

场景：外语学习第 4 天，第一次能把单次 `[初步]` 升级为跨 session 模式。

```markdown
# 2026-06-06 观察日记

## [agent-a | 外语] 09:00 观察

### 行动与体验
- 学了介词 in/on/at 时间用法，主动要求出例句选择
- 答对 7/10 后说"再来一组"，追加了 5 道题

### 想法与洞察
- "on the bus 为什么是 on 不是 in"——对规则背后逻辑有追问

### 习惯与模式观察
- 错题不跳过，每道要求解释原因（连续 4 天出现，跨 session 确认，可记录）

### 情绪与状态
- [推断] 答错后追加练习而非跳过 → 稳定，有耐心

### 小记
- 错题：on 2题、at 1题
- 锚点：上一次记录于 06-05 [agent-a | 外语] 段（最后记录：冠词 3 种用法）
```

> **注意：** `习惯与模式观察` 里的条目明确写出了"连续 4 天出现，跨 session 确认"——这是从 `[初步]` 升级为模式的依据，必须写出升级理由。

## 示例 2：完整段落 — 失败过程如实记录

场景：下午学装饰器，卡了很久，最后放弃。不能只记"尝试了装饰器"。

```markdown
## [agent-a | Python] 14:00 观察

### 行动与体验
- 学装饰器，从 functools.wraps 追问到闭包原理，中途卡在"为什么需要 wraps"
- 连续追问 4 次，AI 解释了 3 种角度后才说"好像懂了一点"
- 最终说"装饰器这块一直没吃透，算了先跳过"，切换到下一个任务

### 想法与洞察
- "好像懂了一点"——[大意] 用了"好像"，表达不确定

### 情绪与状态
- [推断] 连续追问 4 次后说"算了先跳过"，切换任务 → 可能有些受挫，选择暂时放弃

### 小记
- 装饰器未完成，停在"为什么需要 wraps"
```

> **反面对照：**
> ❌ "你对装饰器的理解在逐步加深，选择了策略性暂停"——美化了放弃行为
> ✅ 如实记录"算了先跳过"的原话和切换任务的行为
>
> **注意**：`习惯与模式观察` 整块被删除（本次没有跨 session 模式）——这是合法的，不是缺漏。

## 示例 3：完整段落 — 多 agent 同话题

场景：agent-a 上午出方案，agent-b 傍晚落代码，话题都是 project-x。

```markdown
## [agent-a | project-x] 10:00 观察

### 行动与体验
- 写了搜索页优化方案，画了交互流程图
- 方案里坚持"搜索框必须支持键盘完全操作"，拒绝了 AI 给出的鼠标方案

### 想法与洞察
- "键盘操作是基本权利，不是可选项"——原话

### 习惯与模式观察
- 对无障碍/键盘操作的坚持 [初步，待跨 session 确认]

### 情绪与状态
- [推断] 主动拒绝 AI 方案并给出替代理由 → 对这个判断有明确立场

## [agent-b | project-x] 20:15 观察

### 行动与体验
- 把 agent-a 的搜索方案落成代码，逐条对照需求，实现一个标记一个
- 发现方案里有一处交互描述模糊，停下来确认后再继续

### 习惯与模式观察
- 跨 agent 分工：agent-a 出方案 → agent-b 落代码（第 2 次出现，跨 session 确认）

### 小记
- 参见今日 [agent-a | project-x] 段
```

## 示例 4：完整段落 — 同天同话题多次触发（增量补写）

```markdown
## [agent-a | Python] 10:00 / 14:30 观察

### 行动与体验
- （10:00）学了生成器，反复跑示例代码，追问"yield 和 return 的本质区别"
- （14:30）做了 3 道 算法题 题，用生成器改写了两道；写完没有提交，说"题太简单了"

### 想法与洞察
- （10:00）"这样写真的节省内存吗"——不接受没验证过的说法
- （14:30）"原来中等难度的题我 15 分钟就能写完"——对自己速度的发现

### 习惯与模式观察
- 上午学理论 → 下午做题验证 [初步，待跨 session 确认]

### 情绪与状态
- [推断]（10:00）连续追问 3 次 + 要求出示例 → 专注探究
- [推断]（14:30）做完后说速度发现，没有追加更多题 → 满足，收束

### 小记
- 算法题 题号：#341、#173、#251
- 生成器笔记已更新到 `08_进阶.md`
```

> **补写规则提示：**
> 标题时间戳最多保留**首次和最近**两个（见标题规范）。
> 各版块内用 `（时间戳）` 区分两次写入的内容。

## 示例 5：轻量段落 — 平淡对话

场景：用户只是例行问了一句工具用法，得到答案后说了声"好的"，没有情绪、没有模式、没有决策。

```markdown
## [agent-a | 外语] 15:20 观察

### 行动要点
- 询问了虚拟语气练习文件的存放位置，确认后继续自习
- 记了 20 个新单词（3500 词第 18-22 页）

### 小记
- #项目：外语
```

> **为什么这样记是对的**：
> - 用户没有表达情绪 → 不写"情绪与状态"
> - 没有重复模式出现 → 不写"习惯与模式观察"
> - 没有值得引用的原话 → 不写"想法与洞察"
> - 但行为发生了 → `行动要点` 如实记录
>
> **反面对照（过度推断，禁止）：**
> ❌ "[推断] 确认文件位置后继续自习 → 学习流程越来越顺畅，对工具的掌控感增强"
> ——用户只是问了个位置，没有表达任何"掌控感"。

## 示例 6：轻量段落 — 随口一问

场景：用户随口问了一句"专升本考试具体哪天"，得到日期后继续干别的。

```markdown
## [agent-a | 数学] 11:05 观察

### 行动要点
- 随口确认了专升本考试时间（2027 年上半年）
- 记了 15 个单词（3500 词第 9-11 页）

### 小记
- #项目：数学 #项目：外语
```

> **反面对照（过度推断，禁止）：**
> ❌ "[推断] 主动询问考试时间 → 对备考节点的关注度提升，时间意识在增强"
> ——随口一问不构成"关注度提升"的证据。过推断准入三问：用户没说（①），行为不唯一映射（②），回放给他会得到"啊？我没这意思"（③）。
