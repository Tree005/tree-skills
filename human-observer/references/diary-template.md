# 观察日记格式模板

> 格式参考与示例。每个版块内嵌写入判定，AI 写之前先过判定句。
> **先做信号判定（完整 vs 轻量），再进入对应模板。**
> 日记不是任务清单：只记录能说明「这个人怎么工作、怎么反应、怎么变化」的行为；纯任务明细留在项目笔记。

---

## 版块写入判定速查

| 版块 | 写入前自问 | 写不了时 |
|------|------------|----------|
| **今日印象** | 我能用 1–3 句说出今天这个人的整体状态或主线吗？有行为证据吗？ | 跳过；不要写空泛形容词 |
| **行为切片** | 这是能说明「他怎么工作/怎么反应」的行为吗？还是纯任务清单？ | 纯任务清单不写 |
| **想法与洞察** | 这是用户说出来的原话或可引用的表达吗？ | 跳过，不转述 |
| **对比与变化** | 和近几天比，有重复、变化或回避吗？ | 没有基线就跳过 |
| **习惯与模式观察** | 这个行为在**不同 session** 中出现过 ≥2 次吗？ | 单次标 `[初步]`；无内容整块删除 |
| **状态线索** | 有可观察的文本信号吗？能写成「信号 → [假设] 状态 + 替代解释」吗？ | **无信号整块删除，不硬凑** |
| **待验证的假设** | 有没有低置信度的观察，值得下次验证？ | 没有就删除 |
| **小记** | 有项目标签、待跟进、锚点吗？ | 可留空 |

> ⚠️ **完整段落 ≠ 所有版块齐全**。只有真的观测到信号才写对应版块。
> 平淡对话写轻量段落（见示例 5、6）。

---

## 标题规范

| 触发次数 | 写法 |
|----------|------|
| 1 次 | `## [agent-a | topic-a] 09:00 观察` |
| 2 次 | `## [agent-a | topic-a] 09:00 / 14:30 观察` |
| 3 次及以上 | `## [agent-a | topic-a] 09:00 / 21:30 观察`（首次 + 最近） |

**禁止**：标题加括号注释；agent 名中英混写；topic 不用注册名。

---

## 段落合并规则

| 条件 | 处理 |
|------|------|
| 同 agent + 同话题，同一天 | 追加到已有段落，标题时间戳按规范更新 |
| 同 agent + 不同话题 | 独立段落（新话题先查 `_topics.md`） |
| 不同 agent + 任意话题 | 独立段落 |
| 用户说"分开写" | 强制新段落 |

## 示例 1：完整段落 — 跨天续写 + 模式升级

场景：topic-a 学习第 4 天，第一次能把单次 `[初步]` 升级为跨 session 模式。

```markdown
# 2026-06-06 观察日记

## [agent-a | topic-a] 09:00 观察

### 今日印象
- 今天的主线是「把规则用起来」：不再只问“为什么”，而是主动要求出题验证。

### 行为切片
- 学完规则后主动要求出例句选择题，答对 7/10 后追加 5 题 → 用练习确认理解，而不是停在听懂。
- 错题不跳过，逐题要求解释原因 → 对“为什么错”比对“答案是什么”更在意。

### 想法与洞察
- “on the bus 为什么是 on 不是 in”——对规则背后的逻辑有追问。

### 对比与变化
- 与 06-05 相比：从“先听讲解”变成“先做题再回头问”；主动要求追加练习是第一次出现。

### 习惯与模式观察
- 错题不跳过，每题要求解释原因（连续 4 天出现，跨 session 确认）。

### 状态线索
- 可观察：答错后没有停下，而是追加练习；连续追问 2 次“为什么”。
- [假设] 连续追问 + 追加练习 → 想把规则弄透（置信度：中）；替代解释：只是想把当天的练习做完。

### 小记
- 错题：on 2 题、at 1 题
- 锚点：上一次记录于 06-05 [agent-a | topic-a] 段（最后记录：冠词 3 种用法）
```

> **注意**：`习惯与模式观察` 明确写出“连续 4 天出现，跨 session 确认”——这是从 `[初步]` 升级为模式的依据。

## 示例 2：完整段落 — 失败过程如实记录

场景：下午学某个抽象概念，卡了很久，最后放弃。不能只记“尝试了”。

```markdown
## [agent-a | topic-b] 14:00 观察

### 今日印象
- 今天的关键词是“卡住”：在一个抽象概念上反复追问，最后选择暂时放下。

### 行为切片
- 从用法追问到原理，中途卡在“为什么需要这层包装”；连续追问 4 次，AI 换了 3 种解释后才说“好像懂了一点”。
- 最后说“这块一直没吃透，算了先跳过”，切换到下一个任务。

### 想法与洞察
- “好像懂了一点”——[大意] 用了“好像”，表达不确定。

### 状态线索
- 可观察：连续追问 4 次；说“算了先跳过”后立即切换任务。
- [假设] 追问后仍说“算了”并切换 → 可能有些受挫，选择暂时放弃（置信度：中）；替代解释：只是判断当前性价比不高，主动排优先级。

### 小记
- 该概念未完成，停在“为什么需要这层包装”。
```

> **反面对照：**
> ❌ “你对这个概念的理解在逐步加深，选择了策略性暂停”——美化了放弃行为。
> ✅ 如实记录“算了先跳过”的原话和切换任务的行为。
>
> **注意**：`习惯与模式观察`、`对比与变化`、`待验证的假设` 整块被删除（本次没有信号）——这是合法的，不是缺漏。

## 示例 3：完整段落 — 多 agent 同话题

场景：agent-a 上午出方案，agent-b 傍晚落代码，话题都是 topic-c。

```markdown
## [agent-a | topic-c] 10:00 观察

### 今日印象
- 今天在方案阶段表现出明确的边界感：先划出“必须支持”的范围，再谈实现。

### 行为切片
- 写了搜索页优化方案，画了交互流程图。
- 坚持“搜索框必须支持键盘完全操作”，拒绝了 AI 给出的鼠标方案 → 对无障碍/键盘操作有明确立场。

### 想法与洞察
- “键盘操作是基本权利，不是可选项”——原话。

### 待验证的假设
- [假设] 对键盘操作的坚持 → 可能来自对“可访问性”的稳定偏好（置信度：低）；替代解释：只是这个项目里恰好重要。下次遇到同类取舍时验证。

### 小记
- 方案已交给 agent-b 落地。

## [agent-b | topic-c] 20:15 观察

### 今日印象
- 落地阶段偏“逐条对齐”：实现一个标记一个，遇到模糊处先停下来确认。

### 行为切片
- 把 agent-a 的方案落成代码，逐条对照需求，实现一个标记一个。
- 发现方案里有一处交互描述模糊，停下来确认后再继续。

### 对比与变化
- 与 agent-a 的“先定边界再实现”形成互补：一个负责取舍，一个负责逐条落实。

### 习惯与模式观察
- 跨 agent 分工：agent-a 出方案 → agent-b 落代码（第 2 次出现，跨 session 确认）。

### 小记
- 参见今日 [agent-a | topic-c] 段。
```

## 示例 4：完整段落 — 同天同话题多次触发（增量补写）

```markdown
## [agent-a | topic-b] 10:00 / 14:30 观察

### 今日印象
- 今天的主线是“从理论到验证”：上午追问原理，下午用题验证。

### 行为切片
- （10:00）学了某个语言特性，反复跑示例代码，追问“这个写法和普通写法的本质区别”。
- （14:30）做了 3 道算法题，用新特性改写了两道；写完没有提交，说“题太简单了”。

### 想法与洞察
- （10:00）“这样写真的节省内存吗”——不接受没验证过的说法。
- （14:30）“原来中等难度的题我 15 分钟就能写完”——对自己速度的发现。

### 对比与变化
- 上午偏“问原理”，下午偏“用题验证”；从理解转向应用。

### 习惯与模式观察
- 上午学理论 → 下午做题验证 [初步，待跨 session 确认]。

### 状态线索
- 可观察：（10:00）连续追问 3 次并要求出示例；（14:30）做完后说速度发现，没有追加更多题。
- [假设]（14:30）说完速度发现就收束 → 满足/收尾（置信度：低）；替代解释：只是当天时间到了。

### 小记
- 算法题号：#341、#173、#251
- 新特性笔记已更新到 `topic-b/进阶.md`
```

> **补写规则提示：**
> 标题时间戳最多保留**首次和最近**两个（见标题规范）。
> 各版块内用 `（时间戳）` 区分两次写入的内容。

## 示例 5：轻量段落 — 平淡对话

场景：用户只是例行问了一句工具用法，得到答案后说了声“好的”，没有情绪、没有模式、没有决策。

```markdown
## [agent-a | topic-a] 15:20 观察

### 印象
- 今天这段很平：问了一个工具位置，确认后继续自习，没有展开。

### 行动要点
- 询问了练习文件的存放位置，确认后继续自习。
- 记了 20 个新单词（词表第 18–22 页）。

### 小记
- #项目：topic-a
```

> **为什么这样记是对的**：
> - 没有情绪信号 → 不写“状态线索”
> - 没有重复模式 → 不写“习惯与模式观察”
> - 没有值得引用的原话 → 不写“想法与洞察”
> - 但行为发生了 → `行动要点` 如实记录
>
> **反面对照（过度推断，禁止）：**
> ❌ “[假设] 确认文件位置后继续自习 → 学习流程越来越顺畅，对工具的掌控感增强”
> ——用户只是问了个位置，没有表达任何“掌控感”。

## 示例 6：轻量段落 — 随口一问

场景：用户随口问了一句考试时间，得到日期后继续干别的。

```markdown
## [agent-a | topic-b] 11:05 观察

### 印象
- 这段只是确认信息，没有展开，也没有明显状态信号。

### 行动要点
- 随口确认了考试时间（2027 年上半年）。
- 记了 15 个单词（词表第 9–11 页）。

### 小记
- #项目：topic-b #项目：topic-a
```

> **反面对照（过度推断，禁止）：**
> ❌ “[假设] 主动询问考试时间 → 对备考节点的关注度提升，时间意识在增强”
> ——随口一问不构成“关注度提升”的证据。过推断准入三问：用户没说（①），行为不唯一映射（②），回放给他会得到“啊？我没这意思”（③）。
